# Serving-only dependencies for the Docker image (M2).
#
# This is the subset of requirements.txt that the API actually imports at request
# time: FastAPI + uvicorn to serve, and TensorFlow to load and run model.h5. The
# training and analysis packages (mlflow, dvc, matplotlib, seaborn, notebook,
# kaggle, scikit-learn, pandas, pytest) are deliberately absent — they would add
# hundreds of MB to an image that is already large because of TensorFlow.
#
# CRITICAL (ADR-002): the tensorflow / numpy / pillow / h5py pins below MUST match
# requirements.txt exactly. A skew there can fail to load models/model.h5 or
# silently shift predictions, and audit check 14 fails the build if they diverge.
#
# The TensorFlow line is architecture-conditional, and this is not premature
# generality — it is a bug fixed the hard way. `tensorflow-cpu` is published for
# **linux/amd64 only**; there is no arm64 Linux wheel. On an Apple Silicon host
# `docker build` defaults to linux/arm64, so a plain `tensorflow-cpu` pin fails
# with "from versions: none" — which reads like a bad pin but is really a wrong
# architecture. Verified against PyPI:
#
#   tensorflow-cpu==2.20.0   manylinux2014_aarch64  -> NOT available
#   tensorflow-cpu==2.20.0   manylinux2014_x86_64   -> available
#   tensorflow==2.20.0       manylinux2014_aarch64  -> available
#   tensorflow==2.20.0       manylinux2014_x86_64   -> available
#
# So: prefer the smaller CPU-only build on amd64 (CI runners, GHCR image), and
# fall back to full `tensorflow` on arm64 (local Minikube on this Mac). Both pin
# 2.20.0, so the version the model was trained with is unchanged either way and
# audit check 14 still passes.

# --- Inference-critical: must match requirements.txt ---
tensorflow-cpu==2.20.0; platform_machine == "x86_64"
tensorflow==2.20.0; platform_machine == "aarch64" or platform_machine == "arm64"
keras==3.15.1
numpy==2.4.6
pillow==12.3.0
h5py==3.14.0

# --- API serving ---
fastapi==0.141.1
uvicorn[standard]==0.52.3
pydantic==2.13.4
# Required for multipart/form-data, i.e. the /predict file upload. FastAPI raises
# at import time without it, so omitting it breaks the container at startup.
python-multipart==0.0.32

# --- Observability (M5) ---
python-json-logger==4.1.0
prometheus-fastapi-instrumentator==8.1.0
